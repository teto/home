  Windows OpenSSH ignores ~\.ssh\authorized_keys for members of Administrators. It reads
  C:\ProgramData\ssh\administrators_authorized_keys instead, and that file needs strict permissions:
  icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

  What doesn't work over SSH

  - Start-Process -Verb RunAs: there's no desktop to show a UAC prompt on.
  - The Windows 11 sudo command: it also needs an interactive UAC prompt.

  If the SSH user isn't an admin

  - Scheduled task (most reliable): create a task that runs as SYSTEM or as an admin with highest privileges. Then start it    
    from SSH:
  schtasks /run /tn "MyAdminTask"
  - PowerShell remoting to localhost with admin credentials:
  Invoke-Command -ComputerName localhost -Credential (Get-Credential) -ScriptBlock { Restart-Service Spooler }
    This needs WinRM enabled. Local admin accounts other than the built-in Administrator get a filtered token unless
    LocalAccountTokenFilterPolicy=1. Domain admin accounts aren't affected.

  The simplest setup is to SSH in as an admin account with its key in administrators_authorized_keys. Everything you run is    
  then elevated.
